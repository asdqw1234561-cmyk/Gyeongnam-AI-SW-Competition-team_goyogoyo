# 배포 준비 작업 정리 (2026-10-02, 브랜치 `hwang2`)

담당: 황승구. AI 실행 방식(Ollama / Claude CLI / API)은 아직 결정하지 않았고, 이 문서는 그와 무관하게 필요한 준비 작업만 다룹니다.

## 1. AI 호출 남용 방지

모든 AI 호출은 `agent/llm.py`의 `llm.chat()` 한 곳을 지나가므로 여기서 한 번에 제한합니다.

| `.env` 항목 | 기본값 | 의미 |
|---|---:|---|
| `LLM_MAX_CALLS_PER_SESSION` | 30 | 브라우저 접속(Streamlit 세션) 1개당 최대 AI 호출 수 |
| `LLM_MAX_CALLS_PER_DAY` | 500 | 서버 전체(모든 사용자 합산) 하루 최대 호출 수. 새로고침으로 세션 제한을 우회해도 넘을 수 없음 |
| `LLM_MAX_INPUT_CHARS` | 4000 | 시스템 프롬프트를 뺀 입력 글자 수 상한 |

- 0으로 두면 해당 제한이 꺼집니다.
- 호출 횟수는 **Streamlit 화면 안에서 호출될 때만** 셉니다. 단위 테스트나 수집 스크립트는 영향을 받지 않습니다.
- 성공·실패와 상관없이 시도한 호출은 모두 셉니다.
- 제한에 걸리면 `LLMLimitError`(`RuntimeError` 하위 클래스)를 던집니다. 기존 agent 코드가 AI 실패를 받아 기본 절차로 넘어가는 흐름을 그대로 타기 때문에 **화면이 멈추지 않습니다.**
  - 추가 질문: AI 질문 없이 진행
  - 가중치 해석: "AI 연결에 실패해…" 안내와 함께 수동 슬라이더 사용 가능
  - 최초 추천 / 주변 위치 분석: `fallback_default`(기본 분석 절차)로 진행
- 입력창 글자 수 제한(`max_chars`)도 추가했습니다.
  - 메인: 희망지역·직장/학교·주거비 예산 100자, 추가 요청사항 500자, AI 추가 질문 답변·자연어 가중치 요청 300자
  - 위치 탐색: AI 분석 요청 300자

검증: `tests/test_llm.py` 15개. 그리고 실제 Streamlit 실행(AppTest)으로 확인했습니다. 위치 탐색 페이지에서 세션 제한을 1회로 두고 AI 분석 버튼을 두 번 누르면, 첫 번째는 `ai_planned`, 두 번째는 AI를 부르지 않고 `fallback_default`로 진행됐으며 예외는 없었습니다.

## 2. requirements 정리

- 실제 `import` 기준으로 **앱 실행용**과 **데이터 수집 스크립트용**을 주석으로 나누고, 패키지마다 `>=하한,<다음 메이저` 범위를 정했습니다.
- `anthropic`은 현재 코드 어디에서도 import하지 않아 제외했습니다.
- `ollama`는 agent 코드가 import하므로, Claude CLI를 쓰더라도 설치는 필요합니다(가벼운 클라이언트 라이브러리).
- 검증: 새 가상환경에 `pip install -r requirements.txt`로 설치한 뒤 전체 테스트를 통과했습니다(Python 3.11, streamlit 1.64.0, pandas 3.0.6, numpy 2.4.6).

## 3. CSV 로딩 캐시 — 측정 결과 불필요, 변경 없음

화면을 한 번 그리고 다시 실행하는 동안 CSV 읽기를 측정했습니다.

| 페이지 | 첫 렌더 | 재실행 | CSV 읽기 시간(2회 합) |
|---|---:|---:|---:|
| 메인(`app.py`) | 0.61초 | 0.17초 | 0초 |
| 위치 탐색(`pages/user.py`) | 0.93초 | 0.16초 | 0.01초 |
| 정부용(`pages/government.py`) | 0.50초 | 0.17초 | 0.03초 (22회 읽기) |

가장 무거운 버스정류장 데이터는 이미 파일 수정시각 기반 캐시가 있고, 편의점 좌표도 마찬가지입니다. 지역 지표 CSV는 자주 읽지만 파일이 작아 합계 0.03초 수준이라, 팀원 코드를 고칠 만큼의 효과가 없어 그대로 두었습니다.

## 4. 화면 문구 정리

- 사용자에게 보이는 "Ollama", "qwen3.5:4b" 표기를 실제 사용 중인 백엔드 이름(`llm.backend_label()` → `로컬 Ollama` / `Claude(로컬 CLI)`)이나 "AI"로 바꿨습니다.
  - 대상: `app.py` 안내 문구 1곳·로딩 문구 2곳·오류 문구 1곳, `pages/user.py` 안내 문구 2곳, agent 오류 메시지 4곳
- 상태 코드(`"ollama_error"` 등)와 변수명은 다른 코드가 의존하므로 바꾸지 않았습니다.
- 데이터 출처·기준일은 세 페이지 모두 이미 표시되고 있어 추가 작업이 없었습니다.
