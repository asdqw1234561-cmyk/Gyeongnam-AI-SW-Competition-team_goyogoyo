# 프로젝트 헌법 (PROJECT CHARTER)

> 거의 바꾸지 않는 문서다. 개발 Agent(`/steward`, `/dev`)는 모든 작업 전에 이 문서를 기준으로 "주제 안에 있는가"를 판단한다.
> 바꾸려면 사용자 승인이 필요하고, 바꾼 이유를 `DECISIONS.md`에 남긴다.
> 구현 규칙(데이터·점수·좌표·테스트·Git)은 `CLAUDE.md`가 기준이다. 이 문서는 "무엇을, 왜, 무엇을 하지 않는가"만 다룬다.

## 1. 해결하는 문제

경남으로 이주하거나 정착하려는 사람은 낯선 지역의 교통·의료·생활편의·주변 시설 데이터를 여러 곳에서 직접 찾아야 하고, 각 데이터의 의미와 한계도 스스로 판단해야 한다.

## 2. 대상 사용자

경상남도로 이주를 준비하거나 막 정착한 사람. 지역 사정을 잘 모르고, 공공데이터를 직접 찾아 비교할 시간이나 방법이 부족하다.

## 3. 제품 비전과 MVP 범위

- 비전(장기): **경남 이주자 맞춤형 생활권 탐색 AI Agent**
- MVP(현재 구현·데이터 범위): **경상남도 22개 지역** — 창원시 5개 구(의창·성산·마산합포·마산회원·진해) + 시 7곳 + 군 10곳 (2026-10-04 사용자 승인, DEC-20)
- 비교는 **같은 유형끼리**(창원시 구끼리 / 시끼리 / 군끼리) 인구 1만 명당으로 한다(DEC-21). 유형이 다른 지역을 한 점수로 비교하는 것처럼 표현하지 않는다.
- 주거비·교육(점수)·직장 접근성 축과 행정동 단위 비교는 아직 미확보다. 화면·문서·발표에서 이를 지원하는 것처럼 표현하지 않는다.

## 4. 핵심 Agent Workflow

```
사용자 조건 입력(자연어 포함)
 → Goal     : Agent가 목표를 이해하고 부족한 조건은 추가질문으로 확인
 → Planning : 필요한 분석 순서와 도구를 계획
 → Reasoning: 상황에 맞는 데이터·도구 선택
 → Tool Use : Python이 검증한 도구만 실제 공공데이터로 실행(점수·개수는 Python이 계산)
 → Feedback : 결과를 관찰하고 AI 설명을 Python이 검증, 실패하면 재작성 또는 Python 요약
 → 결과 설명(출처·기준일·한계 포함)
 → 특정 위치 선택 → 위치 Agent가 주변 생활시설 도구 실행 → 검증
 → Memory   : 후속 질문에서 이전 대화·승인 상태를 이어서 재분석
```

AI 역할: 자연어 이해, 목표 판단, 계획, 도구 선택, 결과 설명, 후속 판단.
Python 역할: 실제 데이터 조회, 점수 계산, 좌표·반경 통제, 도구 호출 검증, 미지원 요청 차단, AI 결과 검증, 출처·기준일 관리.
**AI가 실제 데이터 값을 만들어서는 안 된다.**

## 5. 하지 않을 것 (주제 변질 금지)

- 일반 부동산 추천 / 매물·시세 서비스
- 단순 지도 검색 서비스
- 단순 챗봇(1회 질의응답)
- 단순 지역 순위 서비스("어느 구가 1등" 단정)
- 관광 추천 서비스
- 일반적인 경남 정보 검색 서비스
- 모든 것을 해주는 범용 AI 비서

새 기능은 항상 "이주자의 생활권 탐색" 문제 안에 있어야 한다.

## 6. 데이터 신뢰 원칙 (요약 - 세부는 CLAUDE.md 1·3·4절)

- 확보: 구별 버스정류장 수, 의료기관 수, 편의점 등록 업소 수 / 위치 기반: 버스정류장, 편의점
- 미확보: 통근·이동시간, 배차간격, 도보경로, 위치 기반 의료기관, 월세·전세, 범죄율, 응급실 접근성 등
- 데이터가 없으면 "미확보"로 표시하고 AI가 추정해 채우지 않는다. 다른 데이터로 억지로 대신 답하지 않는다.
- 출처와 기준일을 결과와 함께 유지한다.

## 7. 새 작업 채택 기준 (6문항)

1. 현재 프로젝트의 문제(§1)를 더 잘 해결하는가?
2. 경진대회 평가 기준(`COMPETITION_REQUIREMENTS.md`)과 관련이 있는가?
3. End-to-End 시연을 더 강하게 만드는가?
4. 확보된 데이터로 검증 가능한가?
5. 기존 Agent Workflow(§4)와 자연스럽게 연결되는가?
6. 단순 기능 추가가 아니라 Agent의 판단·도구 실행·검증 과정에 기여하는가?

대부분 "아니오"면 구현하지 않고 이유를 보고한다.

## 8. 주제 변경 조건

- §5의 서비스 유형 쪽으로 기울어지는 기능

- 새로운 외부 데이터 도입
