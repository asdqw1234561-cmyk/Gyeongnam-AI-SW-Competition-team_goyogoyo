## 확정된 결정

### DEC-01 · 2026-10-01 · AI는 판단·설명, 숫자는 Python
AI는 요청 해석·계획·도구 선택·설명만 하고, 시설 수·점수·거리는 Python이 계산한다. AI의 도구 호출과 가중치 제안은 Python 검증 후에만 실행한다.
이유: 공공데이터 기반 서비스에서 AI가 수치를 지어내면 신뢰를 잃는다. 대회도 AI 오류 대책을 평가한다(R-EV-6, R-ETH-5).
근거: `CLAUDE.md` §1

### DEC-02 · 2026-10-01 · MVP 범위는 창원시 5개 구
실제 확보 데이터가 창원시 5개 구뿐이므로 MVP 범위를 여기로 고정하고, 경남 전체는 장기 비전으로만 표현한다.
근거: `CLAUDE.md` §3, `README.md`, 커밋 ce4f048(B10)

### DEC-03 · 2026-10-01 · 점수는 min-max 상대 비교, 계산식 불변
5개 구 사이 min-max 정규화 + 승인된 가중치 합. `analysis/scoring.py`가 유일한 점수 계산 경로이며 계산식 변경은 사전 보고 대상이다. 구별 점수와 위치 주변 시설 수는 섞지 않는다.
근거: `CLAUDE.md` §2·4

### DEC-04 · 2026-10-02 · 의료 지표 이름은 "의료기관 수"
전 종별 합산이라 "병원 수"는 과장이다. 코드 문구(B1)와 CSV 지표명(B8)을 모두 바꿨다.
근거: 커밋 86a1ee4, `docs/backlog.md` B1·B8

### DEC-05 · 2026-10-02 · 위치 Agent는 MCP 반복형 구조 유지
팀원(hwang3)이 MCP 위치 Agent를 계속 쓰므로 M1(MCP 제거, agent_loop로 통일)을 취소하고 hwang3 통합 결과를 기준으로 삼았다. 계획형 경로(Ollama + agent_loop)는 폴백·대안 경로로 유지한다.
이유: 팀원 작업과의 충돌 방지, Claude가 도구를 직접 반복 호출하는 장면이 Agent 구현성(R-EV-2) 시연에 유리.
근거: 커밋 34ea8cd(M2), `docs/backlog.md` M1·M2

### DEC-06 · 2026-10-02 · AI 백엔드는 LLM_BACKEND 하나로 결정
위치 Agent도 `LLM_BACKEND`를 따르고(claude_cli → MCP, ollama → 계획형), `LOCATION_AGENT_BACKEND`는 명시했을 때만 덮어쓴다.
근거: 커밋 4316951(N1)

### DEC-07 · 2026-10-02 · AI 답변 숫자 검증 기준 통일
MCP·계획형 두 경로 모두 `agent_loop.verify_answer`로 검사하고, 실패하면 Python 요약으로 대체한다(경고만 띄우던 방식 폐기).
이유: 같은 질문에 경로마다 다른 신뢰 수준이 나오면 안 된다. 엄격함으로 생기는 일부 탈락(목록을 세어 만든 개수 등)은 의도된 결과.
근거: 커밋 78ec6e0(N2)

### DEC-08 · 2026-10-02 · 빈 스텁 파일은 삭제하지 않고 "미구현" docstring
`agent/agent_state.py`는 팀원 구현과 충돌 방지를 위해 제외했다.
근거: 커밋 8e8c7fe(B9)

근거: `CLAUDE.md` §2

### DEC-10 · 2026-10-02 · 자율 개발 Agent 환경 도입 (/steward)
- 사람이 손으로 관리하던 `docs/backlog.md` 대신, Agent가 `docs/agent/`(헌법·요구사항·현재 상태·결정·평가 매트릭스)를 읽고 스스로 갱신하는 구조를 쓴다. backlog는 Agent가 관리하는 작업 큐·이력으로 유지한다(기존 이력 보존).
- 공식 대회자료는 `references/`(읽기 전용)에 두고, `.claude/scripts/ref_scan.py`가 해시로 변화를 감지·추출, SessionStart hook이 세션 시작 때 알린다.
- 실행 단계는 기존 `/dev` 절차를 재사용한다(중복 skill을 만들지 않음).
- 자율 루프는 `jhy-next` 브랜치에서만 코드를 수정한다.
이유: 주제·대회 기준을 잃지 않고 장기간 일관되게 개발하기 위함. 사용자가 MD를 직접 관리하지 않아도 되게 하기 위함.
근거: 이 문서, `.claude/skills/steward/SKILL.md`

### DEC-11 · 2026-10-02 · 최우선 목표를 "핵심 Agent 추천 품질"로 변경
제출자료 작성보다 추천 품질을 먼저 완성한다. 목표는 "가장 좋은 지역 하나"가 아니라 "사용자 조건에 따라 장단점이 다른 현실적인 정착 후보군 탐색"이다. 신규 화면·발표자료·영상·대규모 리팩터링은 당분간 후순위.
- 후보 역할(최적·균형·대안)과 Critic은 기존 `score_result`의 축별 정규화 점수만으로 결정적으로 계산한다(새 점수 계산식 없음, LLM은 점수·후보를 만들지 않음).
- 데이터가 없는 축(주거비·교육·직장 접근성)은 "미확보"로 남기고, 그 축이 필요한 후보 유형(가성비 = 주거비)은 "산출 불가"로 표시한다.
근거: 사용자 지시(2026-10-02), `CURRENT_STATE.md` 추천 품질 분석

### OPEN-3 · 정부용 화면(pages/government.py)의 위치
이주자 생활권 탐색이라는 핵심 주제와 직접 연결되지 않는다. 발표에서 "확장·사업화(지자체 활용)" 근거로 쓸지, 시연 흐름에서 빼고 부가 기능으로 둘지 결정 필요. 코드 삭제는 제안하지 않는다.
