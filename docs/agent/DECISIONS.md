### DEC-12 · 2026-10-02 · 방향성 피드백은 "LLM 추출 + 결정적 배율 규칙 + 승인"
- LLM은 발화에서 대상 축·방향(increase/decrease)·강도 표현 여부만 구조화해 추출한다. 축 이름은 Python이 다시 판정한다(미확보 축·없는 축은 전체 거절, 문장에 없는 축이면 되묻기).
- 조정량은 Python 규칙: 대상 축 ×배율(높이기) 또는 ÷배율(낮추기) 후 합 100%로 재정규화. 배율은 표현 없음 1.5 / "조금" 1.25 / "많이·훨씬" 2.0. 0% 축 높이기는 강도별 10/20/30% 고정 비중.
  이유: 다른 축 사이 비율을 보존하고, 같은 강도로 높였다 낮추면 정확히 원래 가중치로 돌아오며(가역), 축이 0%로 떨어져 평가에서 사라지는 일이 없다. "±N%p" 가산 방식은 되돌림이 정확하지 않고 0% 경계 처리가 임의적이라 택하지 않았다.
- 자동 적용하지 않고 변경될 가중치를 보여준 뒤 승인 시에만 재평가한다. 무시한 제안도 approved=False로 기록한다.
- 슬라이더·숫자 자연어·방향성 자연어·되돌리기는 하나의 재평가 경로(`analysis.feedback.reevaluate`)를 쓴다.
근거: 사용자 지시(2026-10-02), backlog R2

### DEC-16 · 2026-10-03 · 설명은 "Python 기본 설명 + 선택적 AI 다듬기"로 통일
- 경로: candidate_review → explanation_facts → render_explanation(기본 설명, 항상 사실) → AI 다듬기 1회(재시도 없음) → 검증 → 실패 시 기본 설명. 최초 추천(정상·AI 계획 실패 모두)과 피드백 재평가가 같은 `explain_from_facts`를 쓴다.

- 검증 기준은 기본 설명: 새 숫자 금지, fact_violations 중 기본 설명에 없던 새 위반만 거부(R5 규칙의 휴리스틱 오탐이 기본 설명에도 똑같이 나오면 무시), 역할·구·미확보 축·반영 못 한 조건 누락 금지. R5 규칙은 위반을 '모두 모으는' 형태로만 바꿨고 새 규칙은 추가하지 않았다.
- 리뷰어 AI는 추가 조회(참고 지표·가정 계산) 여부만 판단한다.
이유: 4B 모델이 틀려도 서비스 설명 품질이 떨어지지 않게(기본 설명이 항상 정답), 의미 검사 규칙을 계속 늘리는 방식을 멈추기 위해.

### DEC-15 · 2026-10-03 · 강점·약점·대소관계는 Python이 확정하고 LLM은 옮기기만 한다 (explanation_facts)
- 판정 규칙: 축별 5개 구 순위 1~2위 강점 / 3위 중립 / 4~5위 약점(analysis/candidates.py 상수와 동일), 현재 3축은 모두 "높을수록 좋음".
- 관찰 내용에는 explanation_facts만 넣고, 같은 숫자를 두 번 보내지 않는다(순위표는 facts에 없는 구만).
- 검증은 같은 사실 기준: 강점↔약점 뒤집기, "가장 많다/적다"는 1위/최하위만, "A가 B보다"는 실제 점수 방향, 지배는 확정된 방향, 미확보 축은 강점·약점으로 말할 수 없음, "N개 중 M개"는 실제 값.

이유: 규칙으로 문장 패턴을 하나씩 막는 방식(R5 초기 시도)은 4B 모델의 다양한 의미 오류를 따라가지 못한다. 판단을 Python으로 옮기면 검증 기준도 하나가 된다.

### DEC-14 · 2026-10-03 · AI 설명은 Agent가 확정한 후보·Critic을 "설명만" 한다
- 관찰 내용에 candidate_review를 구조화해 넣고(Critic은 계산값이 든 메시지 대신 facts만), AI는 후보를 고르거나 바꾸지 않는다.
- 결정적 검사: 숫자(기존) + 판단 범위 표시("확보" 언급 필수, 미확보 축이 있을 때) + 과장 표현 금지 + 미확보 축 언급은 "미확보/반영 못 함" 맥락만 + 역할과 함께 말한 구가 확정 결과와 일치. 실패 시 재작성 1회 후 Python 요약.
- 입력 길이 제한(4000자)은 올리지 않고 관찰 내용을 줄인다: 공백 없는 JSON, 중복 제거, 후보군이 있을 때 순위표는 요청 후보 + 역할 구만(전체 순위는 화면 표에 있음).
- 피드백 재평가 뒤에도 같은 검사로 설명한다(추가 도구 없이 답변만).
근거: 사용자 지시(2026-10-03), backlog R4
