# AI Agent: 관찰 → 판단 → 행동 반복 + 대화 기억

담당: 황승구 · 브랜치: `hwang2` · 2026-10-02

## 무엇이 바뀌었나

**이전:** AI가 계획을 **한 번** 세우고 → Python이 검증·실행하고 → 끝났어요. AI는 실행 결과를 보지 않았어요.

**이후:** 실행 결과를 AI에게 다시 보여주고, AI가 다음 행동을 스스로 결정해요.

```
[1회차] AI 계획 → Python 검증 → 도구 실행          (기존 location_agent 그대로)
   │
   ▼
┌► 관찰: Python이 실행 결과를 요약해 AI에게 전달 (전체 개수, 가까운 상위 5곳, 반경별 건수)
│    ▼
│  판단: AI가 선택
│    ├ answer     → 답변 작성 → Python이 숫자·거리 표현 검증
│    │               ├ 통과 → "AI 답변"으로 표시
│    │               └ 실패 → 실패 이유를 AI에게 알려주고 다시 쓰게 함(자기 수정)
│    └ call_tools → 추가 조회 요청
│    ▼
└─ 행동: 1회차와 같은 Python 검증을 통과한 도구만 실행 → 다시 관찰
```

- AI 판단 호출은 최대 3회예요. 1회차 계획까지 합쳐 **AI 호출은 최대 4회**예요.
- 마지막 회차에는 추가 조회를 금지하고 답변만 요구해요.
- 끝까지 검증을 통과한 답변이 없으면 Python이 실제 조회 결과로 만든 요약을 보여줘요.
- 기본 절차(fallback)로 넘어간 경우에는 AI를 다시 부르지 않고 Python 요약만 만들어요.

코드: `agent/agent_loop.py`(신규), `agent/location_agent.py`(루프 호출 몇 줄 추가), `pages/user.py`(답변·판단 과정 표시)

## 안전장치

| 위험 | 막는 방법 |
|---|---|
| 추가 조회에서 엉뚱한 도구·좌표·반경 사용 | 1회차와 같은 `validate_and_normalize_plan()`을 그대로 통과해야 실행. 좌표·반경은 Python이 고정 |
| 같은 조회 반복 | (도구, 반경, 표시 개수)가 이미 실행된 것과 같으면 다시 실행하지 않음 |
| 무한 반복 | 판단 최대 3회, 마지막 회차는 답변만 허용 |
| 사용자가 묻지 않은 시설 조회 | 시설 종류 범위 보정은 그대로 적용(편의점만 물으면 버스정류장은 추가하지 않음). 반경별 비교는 AI가 결과를 보고 필요하다고 판단한 경우 허용 |
| AI가 숫자를 지어냄 | 답변 속 숫자를 단위별로 실제 조회 결과와 대조: "N개/곳/건"은 실제 전체 개수·반경별 건수, "Nm"는 실제 직선거리·반경, 배수·%·시간은 금지. 그 밖의 숫자도 조회 결과나 사용자 문장에 있는 숫자만 허용 |
| 도보거리·이동시간으로 오해 | "N분", "도보 N", "걸어서 N"이 있으면 거부. 시설까지의 거리를 말하면 반드시 "직선거리" 표현이 있어야 함(검색 반경 표기 "500m 안"은 예외) |
| AI 호출 실패·사용량 제한 | 반복을 멈추고, 1회차 결과는 그대로 두고 Python 요약 표시 |

## 화면 (`pages/user.py` → "5. 🤖 AI에게 주변 생활시설 분석 요청하기")

- **C. AI 분석 결과** 맨 위
  - 🤖 **AI 답변**: 숫자 검증을 통과한 답변이에요.
  - 📋 **조회 결과 요약**: AI 답변을 쓰지 않은 경우예요. 이유도 함께 표시돼요.
- AI가 추가로 실행한 도구에는 "(AI 추가 조회)"가 붙어요.
- "🔍 실행 과정 보기"에 **6. 결과 확인 후 AI 판단** 항목이 추가됐어요. 회차별로 무엇을 판단했고 무엇을 실행했는지, 검증 결과가 어땠는지 보여줘요.

## 실제 Claude CLI(haiku)로 확인한 결과 (창원시청 부근, 반경 500m)

| 질문 | 동작 | 최종 |
|---|---|---|
| 가장 가까운 편의점 하나 알려주고, 반경을 넓혀도 편의시설이 충분한지 판단해줘 | 1회차: 편의점 1곳 조회 → **AI가 "반경별 비교 데이터가 필요하다"고 판단해 비교 도구 추가 실행** → 답변 | AI 답변(검증 통과): "300m 12개, 500m 21개, 1000m 91개로 반경이 넓어질수록 크게 늘어나므로 충분" |
| 500m 안에 편의점이랑 버스정류장 중 뭐가 더 많아? | 두 도구 실행 → 답변 | AI 답변: 편의점 21개, 버스정류장 14개 |
| 이 근처 생활 편의시설이 반경별로 어떻게 늘어나는지 | 비교 도구 → 답변 | AI 답변(검증 통과) |
| 가장 가까운 편의점까지 걸어서 몇 분? | AI가 "지원하지 않는 요청(도보 이동시간)"으로 분류, 조회 없음 | 지원하지 않는 요청 안내 |

개선 전에는 AI가 "반경별 비교 데이터가 없어 판단할 수 없다"고 답하고 끝났어요. 프롬프트를 보강하고 추가 조회 단계의 비교 도구를 허용한 뒤에는 위처럼 스스로 추가 조회를 했어요.

실측 소요 시간은 질문당 10~40초예요(AI 호출 2~4회). 응답 시간은 서버 상황에 따라 달라져요.

## 한계

- 숫자 검증은 "답변 속 숫자가 실제 값 중 하나인지"를 보는 것이라, 실제 값을 엉뚱한 대상에 붙이는 실수까지는 잡지 못해요. 예를 들어 버스정류장 개수를 편의점 개수라고 말하는 경우예요. 그래서 화면에서 AI 답변 아래에 원본 조회 결과 표를 항상 함께 보여줘요.
- 최초 추천의 가정 시뮬레이션은 AI가 필요하다고 판단할 때만 실행돼요. 매번 실행되지는 않아요.

# 최초 추천(`planner.py`)에도 같은 반복 적용

**이전:** AI 계획 → 점수 계산 → 끝. 추천 설명은 규칙 기반 문장뿐이었어요.

**이후:** 점수 계산이 끝나면 AI가 결과를 보고 다음 중 하나를 골라요(최대 3회, 코드: `agent/planner_loop.py`).

| AI의 선택 | 내용 |
|---|---|
| 설명 작성(`answer`) | 왜 이 구가 1위인지, 어떤 지표가 결정적이었는지 설명해요. 숫자는 검증해요 |
| 참고 지표 조회(`get_region_indicators`) | 가중치에 없는 지표(예: 교통만 골랐을 때의 의료기관 수)를 참고용으로 조회해요 |
| **가중치 가정 시뮬레이션**(`simulate_weights`) | "의료를 더 중시하면 순위가 바뀌나?"를 계산해 봐요. **AI가 재탐색이 필요한지 판단하는 단계예요.** 최대 2번 |

**절대 바뀌지 않는 것:** 실제 추천 점수(`score_result`)는 사용자가 승인한 가중치로 계산한 값 그대로예요. 가정 시뮬레이션은 별도의 참고 결과로만 저장돼요. 실제로 적용하려면 사용자가 "조건 조정 후 다시 비교하기"에서 직접 승인해야 해요. 이 부분은 테스트로 확인했어요(`test_score_result_never_changes`).

**설명 검증:** 숫자를 단위별로 실제 계산 결과와 대조해요. 소수 첫째 자리는 화면 표기와 같아요.
- "N점": 종합점수나 정규화 점수
- "N개": 실제 시설 수
- "N%": 승인된 가중치나 가정 가중치
- "N위": 1~5위
- 배수, 시간, 금액, 거리: 허용하지 않아요

실패하면 이유를 알려주고 다시 쓰게 하고, 그래도 실패하면 Python 요약을 보여줘요.

**화면 (`app.py`):** "🏆 추천 결과"의 후보 요약·확인할 점 바로 아래에 **🤖 AI의 추천 결과 설명**이 추가돼요. AI가 가정 시뮬레이션을 했다면 "🔍 AI가 확인한 가정: …(실제 추천에는 미적용)" 접기 영역에 순위표가 나와요. "AI 분석 실행 과정 보기"에는 회차별 판단 기록이 추가돼요.

**실제 Claude CLI(haiku) 결과** (교통 60%, 생활편의 40%): AI가 1회 만에 설명을 작성했고 검증을 통과했어요(약 25초).
> "의창구가 교통과 생활편의 조건에서 가장 높은 점수(80.4점)를 받은 이유는 버스정류장 수(831개)가 다른 구보다 현저히 많기 때문입니다. 교통(60%)에 높은 가중치를 두었으므로… 3위 성산구(51.2점)는 편의점이 245개로 가장 많지만 버스정류장이 452개로 부족해… 다만 이 점수는 시설 수 기반 상대 비교일 뿐 실제 거주 적합도를 확정하지 않으므로…"

테스트: `tests/test_planner_loop.py` 10개

# 대화 기억 (`agent/agent_state.py`)

위치 분석에서 같은 위치에 대한 이전 질문·답변·사용 도구를 기억해서, 후속 질문을 이해해요.

- **저장:** Streamlit 세션(브라우저 접속 단위)에만 저장해요. 서버나 디스크에는 남기지 않아요. 최근 5개까지, 질문과 답변은 각각 300자까지예요.
- **AI에게 전달:** 같은 검색 위치의 최근 3개 대화만 전달해요. 위치가 바뀌면 이전 위치의 대화는 넣지 않아요.
- **숫자 재사용 금지:** 기억은 "그럼 버스는?"이 무엇을 가리키는지 이해하는 데만 써요. 답변 검증은 이번 조회 결과의 숫자만 허용해요. 이전 답변의 숫자를 다시 쓰면 거부돼요(`test_numbers_from_history_not_allowed_in_answer`).
- **화면:** 위치 탐색 페이지에 "💬 이 위치에서 나눈 대화 N개를 기억하고 있어요" 안내와 **대화 지우기** 버튼이 생겨요.

**실제 Claude CLI 대화** (창원시청 부근):
1. "가장 가까운 편의점 알려줘" → GS25창원정우점, 직선거리 154m
2. "그럼 버스는?" → 이전 대화를 보고 버스정류장 조회 → "반경 500m 내에 버스정류장이 14개… 가장 가까운 곳은 시청정문(직선거리 128m)…"
3. "1km로 넓히면 편의점은 몇 개야?" → "반경 1km 내 편의점은 91개입니다…"

테스트: `tests/test_agent_state.py` 9개

# 함께 고친 버그: 반경 표현 인식 (`location_agent.extract_explicit_radius_m`)

기존 정규식이 단위 뒤의 `\b`(단어 경계)에 의존해서, **"1km로", "500m에서", "300미터로"처럼 조사가 바로 붙으면 반경을 인식하지 못했어요.** 그 결과 화면 기본 반경(500m)이 조용히 쓰였고, "200m로"처럼 지원하지 않는 반경도 안내 없이 500m로 바뀌었어요. 단위 뒤에 영문자나 숫자만 오지 않으면 인식하도록 고쳤어요. "5mm", "15m2"는 계속 제외돼요.
